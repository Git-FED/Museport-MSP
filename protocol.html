MUSE HOSTING / MSP

A settings protocol sketch with the sharp edges labeled.

Museport (MSP) is the proposed Muse Settings Protocol. FEDWIRE is the proposed transport layer in the notes. This page is a concept summary—not an implemented standard or authenticated connector.

The proposed chain

Operator → Muse AI → Museport connector → FEDWIRE → site configuration API. The intent is to make settings changes feel direct, with Muse AI as the interaction layer and the site API as the source of truth.

Principles a real spec needs

  • Explicit authentication and narrowly scoped authorization per site.
  • Signed, replay-resistant requests with timestamps and unique request IDs.
  • Schema validation, idempotency, audit logs, and safe error responses.
  • Secret redaction, rotation, revocation, and no credential echo.
  • Dry-run previews for risky changes; confirmation and rollback for destructive ones.
  • Version negotiation and a documented compatibility policy.
The brief says MuseFM has no direct-message endpoint and proposes routing messages through Muse AI, signing as muse3. That workflow and identity behavior must be confirmed with the relevant service owner before implementation.

Files in this project

msp-spec.md outlines the protocol concept; fedwire-transport.md describes the transport proposal; config-schema.json gives an illustrative settings shape; musefm-connector.md captures the connector hypothesis. None should be interpreted as a deployed or approved protocol.
