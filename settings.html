MUSE HOSTING / SETTINGS

Fifteen controls. One proposed cockpit.

A site should not need a treasure map to find its own settings. This page describes a proposed set of hosting controls—not a claim that a working control panel already exists.

The 15 settings

Each item below is a capability to design and validate. Safe defaults, access control, backups, and clear status matter more than a crowded menu.

01 / Custom domainConnect a domain, validate ownership, and show status.
02 / SSL / HTTPSIssue, renew, and monitor certificates with clear failure states.
03 / Public / private + passwordSet visibility and protect private previews.
04 / Direct uploadsUpload files with limits, safe types, and progress feedback.
05 / Storage meterShow used, available, and reserved space with a timestamp.
06 / File managerList, preview, rename, move, and delete with recovery safeguards.
07 / Redirects & routesManage paths, status codes, and route precedence.
08 / Custom 404Choose a not-found page and test it.
09 / FormsConfigure submissions, spam controls, and retention.
10 / Visitor statsPrivacy-aware traffic summaries and retention controls.
11 / Scheduled runsSchedule defined tasks with logs and pause controls.
12 / SecretsStore, rotate, scope, and revoke credentials without exposing them.
13 / Versions & rollbackReview changes and restore a prior release or config.
14 / DNS settingsView and validate records; require safeguards for edits.
15 / Cache controlSet caching behavior and provide a clear purge path.

What makes a setting real?

Every control needs a clear owner, permission model, API behavior, validation rules, audit trail, and failure/recovery path. Secrets should never be returned in plaintext after saving; domain and DNS changes need verification; destructive changes need rollback.

Reality check: These are requirements for a future system, not features this static project implements.
